## Совместимые устройства

Прошивка работает на «ТВ-часах» класса **SmallTV / SmallTV-Ultra** и их
клонах с платой **ESP8266** (модуль ESP-12E) и дисплеем **ST7789 240×240**.

| Устройство | Env сборки | Пины (CS/DC/RST) | Проверено |
|---|---|---|---|
| **SD PRO** (мод smalltv-mod) | `sdpro` | CS=15, DC=0, RST=2 | ✅ |
| **SD PRO** (alt-ревизия) | `sdpro_alt` | CS=15, DC=2, RST=4 | ✅ |
| SmallTV / SmallTV-Ultra (клон, пины smalltv-mod) | `sdpro` | CS=15, DC=0, RST=2 | ⚠️ электросовместимо |
| NodeMCU / ESP-12E + 1.3" ST7789 240×240 (своя сборка) | `sdpro` | по вашей распайке | ✅ |

Общая электрика у всего семейства:

- MCU **ESP8266** @ 80 MHz, флеш **4 MB, DIO**
- Дисплей **ST7789**, 240×240, RGB565, SPI **40 MHz**
- Подсветка на **GPIO5, активный LOW**

> ❌ **Не поддерживается:** SmallTV-Pro и любые платы на **ESP32**,
> ESP8266 с 1 MB флеша (нужен LittleFS ~1 МБ), экраны кроме ST7789 240×240.
> Узнать плату: откройте корпус — крупная надпись на чипе; либо залейте
> стоковую прошивку GeekMagic и посмотрите лог.

Если у вас «необычные» часы — не начинайте с `SDP_firmware.bin`: соберите из
исходников своим `[env]` в `platformio.ini` (пины и частота SPI там же).

## Что понадобится

| | |
|---|---|
| Аппаратно | USB-UART адаптер на **CH340/CP2102/FT230X** 3.3 В (5 В tolerant у CH340) + 4 провода «мама-мама» **или** штатный программатор часов |
| Софт | [Python 3.8+](https://python.org) + `esptool` (ставить не нужно — команды ниже ставят сами) |
| Драйвер | CH340/CP2102 драйвер (Windows ставит обычно сам; иначе — WCH/Silicon Labs) |
| Файлы | `SDP_firmware.bin` из последнего релиза (⚠️ **не переименовывайте** — внутри отпечаток сборки) |
| Время | 15 минут на первый раз, 1 минута на повторный |

Подключение адаптера к часам:

```
USB-UART 3V3  ->  3V3 часов
USB-UART GND  ->  GND часов
USB-UART TX   ->  RX часов
USB-UART RX   ->  TX часов
```

Часы при этом **питаются от USB-UART** (3V3, ток ~150–200 мА хватает). Никаких
кнопок нажимать не нужно — при подаче питания модуль ESP-12E сам входит в
загрузчик при отсутствии корректной прошивки; на некоторых платах нужно
держать **GPIO0 на GND** в момент включения.

## 1. Резервная копия (штатная прошивка)

**Не пропускайте** — без неё откат к стоку будет невозможен.

```bash
# Windows (COM-порт из Диспетчера устройств, напр. COM5)
python -m esptool --port COM5 --baud 460800 read-flash 0 0x400000 backup-stock.bin

# Linux/macOS
python -m esptool --port /dev/ttyUSB0 --baud 460800 read-flash 0 0x400000 backup-stock.bin
```

Сохраните `backup-stock.bin` в надёжное место. Откат:

```bash
python -m esptool --port COM5 write-flash 0x0 backup-stock.bin
```

## 2. Первая прошивка через USB-UART

### Windows одной кнопкой (`flash_broclock.bat`)

В релизе лежит `tools\flash_broclock.bat`. Положите его в одну папку с
`SDP_firmware.bin` и запустите двойным кликом:

```
flash_broclock.bat
```

Он сам: найдёт порт `USB-SERIAL CH340`, остановит конфликтующий сервис,
предупредит о риске, прошьёт образ и проверит хеш. В конце — «INSTALL
COMPLETED SUCCESSFULLY». Если файл скачан повторно — бат проверит, что `.bin`
совпадает с релизом (antivirus иногда правит загруженные файлы, см. FAQ).

### Windows / Linux / macOS: esptool

```bash
python -m pip install esptool

# Windows
python -m esptool --port COM5 --baud 460800 write-flash 0x0 SDP_firmware.bin

# Linux / macOS
python -m esptool --port /dev/ttyUSB0 --baud 460800 write-flash 0x0 SDP_firmware.bin
```

Ожидаемый финал вывода:

```
Wrote 892512 bytes ... at 0x00000000 in 13.7 seconds ...
Verifying written data...
Hash of data verified.
Hard resetting via RTS pin...
```

Проблемы с портом/баудрейтом — читайте
[«Если что-то пошло не так»](#если-что-то-пошло-не-так).

### Из браузера (веб-прошивка)

Если ставить Python не хочется: откройте в Chrome/Edge
<https://web.esphome.io> → **Connect** → выберите порт → **Install** →
**Choose file** → `SDP_firmware.bin` → Install. Работает через WebSerial,
драйвер CH340 всё равно нужен. Это ровно тот же процесс, что и esptool.

## 3. Первый запуск: подключение к Wi-Fi

1. Часы перезагружаются после прошивки и поднимают точку доступа:

   | | |
   |---|---|
   | SSID | **`BroClock-PRO`** |
   | Пароль | нет (открытая сеть) |
   | Адрес страницы | **<http://192.168.4.1>** |

2. Подключитесь к ней с телефона, откройте `192.168.4.1`.
3. Нажмите **Сканировать сети**, выберите свой Wi-Fi, введите пароль,
   **Сохранить и подключить**. Уже подключённая сеть показывается с полем
   «только чтение» и неактивной кнопкой **Подключено** — это защита от случайной перепрошивки
рабочей сети.
4. Часы уйдут в вашу сеть. Новый **IP** будет показан на экране и в шапке веб
   — запомните/зафиксируйте в роутере (DHCP reservation), чтобы не искать
   заново.
5. Веб-интерфейс теперь открывается по этому IP с любого устройства в сети.

## 4. Повседневные обновления (OTA)

1. Веб → вкладка **Прошивка**.
2. Выберите новый `.bin` → **Обновить прошивку** → подтвердите.
3. Экран замрёт ~30 секунд, устройство перезагрузится. Готово.

**Защита:** принимаются только образы **этой сборки** — в файле ищется
отпечаток (чип, объём флеша, пины дисплея). Чужая прошивка **не запишется**,
старая продолжит работать. Поэтому переименованный или «похожий» `.bin`,
скачанный не отсюда, выдаст ошибку — качайте файл из Releases заново.

## 5. Полная перепрошивка всего флеша

Если нужно всё «как с завода» (или слетел LittleFS): образ
`BroClock_Pro_factory.bin` из релиза — это **вся** 4 МБ память:

```
0x000000  BroClock_Pro_firmware.bin (приложение)
0x140000  assets.bin   (анимации/иконки)
0x1B8000  boot.bin     (заставка включения)
0x300000  icons.bin    (LittleFS, иконки тем)
```

```bash
python -m esptool --port COM5 --baud 460800 write-flash 0x0 BroClock_Pro_factory.bin
```

⚠️ Сотрёт сохранённую конфигурацию — после прошивки снова настройте Wi-Fi
(шаг 3).

## Если что-то пошло не так

| Симптом | Причина | Решение |
|---|---|---|
| Порт `COM5` не появляется | нет драйвера CH340 / кабель «только зарядка» | поставьте драйвер WCH, возьмите data-кабель, другой USB-порт |
| `Failed to connect to ESP8266: Timed out` | нет связи / питание | проверьте распайку (TX↔RX!), общая GND, держите GPIO0 на GND при включении, попробуйте `--baud 115200` |
| `A fatal error occurred: MD5 of file does not match data in flash!` | порча файла скачивания (часто — antivirus) | перекачайте релиз, сверьте MD5 в релизе, добавьте папку в исключения |
| После прошивки белый/шумный экран | не та ревизия платы | перешейте образом для другой ревизии (`sdpro` ↔ `sdpro_alt`) или прошейте фулл-флеш |
| Часы в бутлупе (перезагружаются) | не хватило сектора LittleFS | прошейте `BroClock_Pro_factory.bin` (все 4 МБ) |
| Забыли IP | DHCP сменил адрес | посмотрите на экране часов при старте; в роутере закрепите адрес |
| Погода не обновляется | пустой город / нет ключа OWM | веб → Погода → введите город (или выберите Open-Meteo — он без ключа) |
| OTA отклонил файл | не этот билд / правился | качайте свежий `.bin` из Releases без переименований |

Диагностика: подключитесь монитором порта **115200 8N1** (`pio device
monitor` или Arduino IDE) — в логе видны отпечаток сборки, состояние кэша,
результат Wi-Fi и строки `[wx] [fc] [candle]` при обновлении данных.

## Частые вопросы

**Это мои часы вообще?**
ESP8266 + экран 240×240, в системе — плата с меткой `SD PRO`/`smalltv`.
ESP32 (Pro-линейка) — нет.

**Прошивка стёрёт мои фото/иконки?**
OTA — нет («Прошивка» пишет только приложение). Полный флеш — да.

**Нужен ли ключ OpenWeatherMap?**
Нет: выберите источник **Open-Meteo** — работает без ключа. Ключ OWM
нужен только если хотите именно его.

**Работает без интернета?**
Да — часы, карусель, фото, праздники и последние котировки/погода показаны из
кэша; обновление догонит при появлении сети.

**Как вернуть стоковую прошивку?**
`write-flash 0x0 backup-stock.bin` (ваша копия из шага 1).

**Безопасно ли?**
Весь код открыт (MIT), внешних обращений нет кроме перечисленных API
(CoinGecko, Open-Meteo/OWM, NTP, date.nager.at, ip-api). Пароли Wi-Fi хранятся
в зашифрованном разделе ESP8266, в веб-интерфейсе не отображаются.
